# 관측 (19장)

지표 수집기와 대시보드입니다. 실습용 구성이고, 운영에서는 기관이 이미 쓰는 것에 붙이는
것이 보통입니다(14.2와 같은 판단).

```bash
kubectl apply -f prometheus.yaml
kubectl apply -f grafana.yaml
```

대시보드는 <http://eum.local:8080/grafana> 입니다. 로그인은 실습이라 껐습니다.

## 노트북에서 돌아가게 만든 것

서비스 넷·데이터베이스·브로커가 이미 3GB 를 씁니다(15장). 기본 설정으로 올리면 넘칩니다.

| 무엇 | 값 | 왜 |
| --- | --- | --- |
| 수집 주기 | 15초 | 짧을수록 메모리를 더 쓴다 |
| 보존 기간 | 2시간 | 기본값은 15일이다 |
| 수집기 상한 | 384Mi | 실측 사용량은 25Mi 안팎 |
| 대시보드 상한 | 256Mi | |
| 저장소 | `emptyDir` | 파드와 함께 사라진다. 운영에서는 볼륨(10.3) |

## 켜야 했던 것

애플리케이션 쪽에도 손댈 것이 있었습니다.

| 무엇 | 없으면 |
| --- | --- |
| `micrometer-registry-prometheus` 의존 | `/actuator/prometheus` 가 404 다 |
| `include: …,prometheus` | 같음 |
| `percentiles-histogram` | 응답 시간 분위수가 빈 값이다 — **대시보드는 그려지는데 선이 안 나온다** |
| 파드의 `prometheus.io/scrape` 표시 | 수집기가 그 파드를 안 긁는다 |

셋째가 특히 조용합니다. 화면은 멀쩡한데 값만 없습니다.
