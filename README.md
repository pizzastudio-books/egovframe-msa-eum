# 이음 — 공공 시스템의 쿠버네티스 전환 예제 코드

소상공인 지원금 신청·심사 시스템 **이음**입니다. 한 덩어리로 배포되던 것을 컨테이너로
옮기고, 쿠버네티스에 올리고, 서비스로 나누는 과정을 **단계별 스냅숏**으로 담았습니다.

전자정부 표준프레임워크 실행환경 5.0 · Spring Boot 3.5 · JDK 17 · JPA + QueryDSL ·
MySQL · Kubernetes · Helm · RabbitMQ

## 5분 만에 돌려 보기

```bash
cd local
./up.sh services      # 노트북에 클러스터를 만들고 전부 올린다
```

`/etc/hosts` 에 한 줄이 필요합니다.

```
127.0.0.1  eum.local
```

<http://eum.local:8080> 입니다. 계정은 `admin`(기관 담당자)·`user1`·`user2`, 비밀번호는
모두 `eum12345!` 입니다. 자세한 것은 [`local/README.md`](local/README.md)에 있습니다.

쿠버네티스까지 가기 전이라면 컴포즈로 충분합니다.

```bash
cd eum-mono
./gradlew bootJar
docker compose up -d --build     # http://localhost:8080
```

## 이 코드가 보여 주려는 것

### 나누기 전에 무엇이 걸리는가

`eum-mono` 는 일부러 옮기기 어렵게 되어 있습니다. 공공 사업에서 실제로 마주치는 형태들입니다.

| 무엇 | 어디서 걸리나 |
| --- | --- |
| 인메모리 H2 | 프로세스를 여러 벌로 늘리면 각자 다른 DB 를 갖는다 |
| `@Scheduled` 야간 배치 | 여러 벌로 늘리면 같은 배치가 중복 실행된다 |
| 알림이 접수와 같은 트랜잭션 | 발송이 실패하면 접수까지 실패한다 |
| 타 기관 DB 직결 | 상대 기관이 내려가면 접수도 멈춘다 |
| 첨부 파일이 로컬 디스크에 | 컨테이너가 죽으면 파일도 사라진다 |
| 한 트랜잭션인 접수 흐름 | 나누면 깨진다 |

### 나눈 뒤에 무엇을 지켜야 하는가

접수 한 건이 신청 저장·예산 차감·알림을 한 트랜잭션으로 처리하던 것이, 서비스를 나누는
순간 성립하지 않습니다. `eum-services` 는 그 자리를 이렇게 메웁니다.

```
[본체]  심사 승인 저장 + 아웃박스 기록          ← 한 트랜잭션. 여기까지는 ACID
          │
        발송기가 아웃박스를 읽어 브로커로 발행
          │
[지급]  선정됨 수신 → 지급 지시 → 야간에 금융망 이체
          │
     ┌────┴────┐
   성공        실패
     │          │
[본체]  지급완료로 확정      접수로 되돌림 (보상)
```

- **아웃박스** — 저장은 됐는데 발행 전에 죽으면 이벤트가 사라진다
- **멱등** — 브로커는 한 번 이상 전달을 보장할 뿐이다
- **보상** — 되돌릴 수 없는 것을 되돌리는 대신, 되돌리는 일을 따로 한다

## 확인

모든 시험은 브로커나 데이터베이스를 띄우지 않고 돕니다.

```bash
cd eum-mono     && ./gradlew build      # 60건
cd eum-services && ./gradlew build      # 76건 (서비스 사이 8건 포함)
cd eum-mono/frontend && npm test        # 7건
cd eum-helm     && ./verify.sh          # 매니페스트와 차트가 같은 것을 내는지
```

`eum-services` 의 통합시험은 본체·지급·알림을 한 JVM 에 각각 띄우고, **한쪽이 실제로
내보낸 메시지를 그대로 다른 쪽에 넣어** 사가 한 바퀴를 확인합니다.

## 표준프레임워크 MSA 템플릿과의 관계

업무 코드의 구조는 **전자정부 표준프레임워크 MSA 템플릿**
([eGovFramework/egovframe-msa-edu](https://github.com/eGovFramework/egovframe-msa-edu),
Apache-2.0)을 참고했습니다. 템플릿은 참조 구현이고, 이 코드가 그대로 옮긴 것은 아닙니다.

| 템플릿 | 이음 |
| --- | --- |
| reserve-item-service (예약 물품) | 지원사업 — 총 재고·잔여 재고가 **총 예산·잔여 예산** |
| reserve-request-service (예약 신청) | 신청 |
| reserve-check-service (예약 확인) | 심사 |
| user-service · portal-service | 회원 · 공통코드 |
| 없음 | **지급 · 알림 · 야간 배치**(새로 만듦) |

주요하게 달라진 점은 이렇습니다. 왜 그렇게 했는지는 책에 있습니다.

- **WebFlux + R2DBC → Web MVC + JPA.** 한 프로세스에 WebFlux 와 MVC 를 같이 넣을 수
  없어 한 덩어리 출발점을 만들 수 없습니다.
- **아웃박스·사가·멱등을 더했습니다.** 템플릿은 저장 직후 곧바로 발행합니다.
- **서비스마다 데이터베이스와 계정을 갈랐습니다.** 템플릿은 여섯 서비스가 계정 하나를
  공유하고 그 계정에 전권이 있습니다.
- **게이트웨이는 토큰 검증과 감사 로그만 합니다.** 요청마다 회원 서비스를 부르지 않습니다.
